# 🏢 Кроссплатформенная система бронирования переговорных комнат

Привет! Это наш внутренний проект — бот для бронирования переговорок, который работает одновременно в **Telegram** и **ВКонтакте**. Мы используем Google Sheets как базу данных, чтобы любой сотрудник мог открыть таблицу и посмотреть, кто и когда забронировал комнату. Ничего сложного, но работает надёжно.

## Что умеет

### Для обычных пользователей
- 🏢 **Три переговорные комнаты** с фотографиями и описанием
- 📅 **Бронирование на 7 дней вперёд** — выбираешь дату, время, длительность
- 🕐 **Шаг 30 минут**, максимум 3 часа, рабочие часы 9:00–18:00
- ✅ **Мгновенное подтверждение** — бронь создаётся сразу, без ожидания
- 📋 **Мои бронирования** — список с кнопкой отмены
- 🔗 **Связка Telegram ↔ VK** — забронировал в одном месте, управляешь в другом
- ⏰ **Напоминания за 30 минут** — бот сам напомнит о встрече

### Для администраторов
- 👑 **Админ-панель** — доступна только по ID администратора
- 📊 **Статистика за сегодня** — сколько броней, какие комнаты популярны
- 🚫 **Принудительная отмена** — отменить любую бронь в системе
- 📢 **Массовая рассылка** — отправить объявление всем пользователям

## 🔗 Кроссплатформенная связка аккаунтов (Telegram ↔ VK)

Мы реализовали полноценную связку аккаунтов через отдельный лист `users_auth` в Google Sheets:

**Как это работает:**
1. Пользователь нажимает "🔗 Привязать ВКонтакте" в Telegram
2. Бот генерирует одноразовый код (например, `TGVK4823`), действует 10 минут
3. Пользователь отправляет этот код в VK-бот
4. VK-бот записывает `vk_id` в строку с этим кодом
5. Теперь брони видны в обоих ботах — неважно, где создавались

**Что это даёт:**
- 📋 Общий список броней на обеих платформах
- ❌ Отмена брони из любого мессенджера
- ⏰ Напоминания приходят в оба места (если связаны)

## 🔧 Что мы исправили по ходу разработки

### P0 — Критические баги

**1. VK polling** — изначально был ручной цикл `async for event in polling.listen()`, который обходил middleware vkbottle. Переписали на стандартный `vk_bot.run_polling()`.

**2. Timezone** — везде использовался `datetime.now()` без timezone, из-за чего брони могли "исчезать" при переходе на летнее/зимнее время. Перешли на `ZoneInfo("Europe/Moscow")`, все вызовы заменены на `datetime.now(TIMEZONE)`.

**3. Graceful shutdown** — добавили обработчики `SIGINT`/`SIGTERM`, корректная отмена задач через `asyncio.wait()`.

### P1 — Безопасность данных

**4. Soft Delete** — раньше `cancel_booking()` физически удалял строку из таблицы через `delete_rows()`. Это создавало race condition: если два пользователя одновременно отменяли брони, один мог "промахнуться" мимо строки (индексы сдвигались). Теперь вместо удаления меняется статус на "Отменено" — данные остаются для аудита, а фильтрация работает корректно.

**5. Логирование с ротацией** — `RotatingFileHandler` на 5MB, хранит 3 бэкапа (`bot.log.1`, `.2`, `.3`). Папка `logs/` создаётся автоматически.

### P2 — Защита от спама

**6. Rate Limiting** — минимум 1 секунда между запросами от одного пользователя:
- Telegram: `ThrottlingMiddleware` для aiogram (message + callback_query)
- VK: декоратор `@rate_limit()` на всех хэндлерах

### Фоновые задачи

**7. Автоматические напоминания** — фоновый `reminder_scheduler()` проверяет каждую минуту, есть ли брони через 29–31 минуту. Если да — отправляет уведомление и помечает колонку "Уведомление" как "Отправлено", чтобы не дублировать.

## 🚀 Установка и запуск

### 1. Клонируем репозиторий

```bash
git clone <repository-url>
cd booking-system
```

### 2. Создаём виртуальное окружение

```bash
python3 -m venv venv
source venv/bin/activate  # Linux/macOS
# venv\Scripts\activate   # Windows
pip install -r requirements.txt
```

### 3. Настраиваем Google Sheets

1. Создайте проект в [Google Cloud Console](https://console.cloud.google.com/)
2. Включите **Google Sheets API** и **Google Drive API**
3. Создайте сервисный аккаунт, скачайте JSON-ключ
4. Переименуйте ключ в `service_account.json` и положите в `data/`
5. Создайте Google Таблицу, дайте сервисному аккаунту права **Editor**
6. Скопируйте ID таблицы из URL

### 4. Настраиваем переменные окружения

```bash
cp .env.example .env
```

Откройте `.env` и заполните:

```env
# Telegram
TELEGRAM_BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz

# VK
VK_BOT_TOKEN=abc123def456ghi789jkl012mno345pqr678stu901

# Google Sheets
GOOGLE_SERVICE_ACCOUNT_FILE=data/service_account.json
GOOGLE_SPREADSHEET_ID=1A2B3C4D5E6F7G8H9I0J
GOOGLE_SPREADSHEET_URL=https://docs.google.com/spreadsheets/d/...

# Timezone (опционально, по умолчанию Europe/Moscow)
TIMEZONE=Europe/Moscow
```

### 5. Настраиваем администраторов

В `config.py` найдите раздел `=== АДМИНИСТРАТОРЫ ===` и замените ID на свои:

```python
TG_ADMIN_IDS = [950069853]  # Ваш Telegram ID
VK_ADMIN_IDS = [445181972]  # Ваш VK ID
```

Узнать свой ID можно через ботов @userinfobot (TG) или отправив любое сообщение своему VK-боту и посмотрев логи.

### 6. Добавляем фотографии комнат

```bash
mkdir -p images
# Положите туда:
# images/coworking.jpg — Лофт-Гостиная
# images/big.jpg — Премиум-Бордрум
# images/small.jpg — Стеклянный Опенспейс
```

### 7. Проверяем подключение к Google Sheets

```bash
source venv/bin/activate
python3 test_db.py
```

Должно вывести:
```
✅ Подключение успешно!
📊 Таблица ID: ...
📄 Лист: bookings
```

### 8. Запускаем ботов

```bash
source venv/bin/activate
python3 main.py
```

В консоли увидите:
```
============================================================
ЗАПУСК КРОССПЛАТФОРМЕННОЙ СИСТЕМЫ БРОНИРОВАНИЯ
============================================================
Инициализация Telegram-бота...
Telegram-бот успешно запущен в режиме Polling!
Инициализация VK-бота...
VK-бот успешно запущен в режиме LongPoll!
✅ Reminder scheduler запущен
```

## 🛡️ Безопасность

| Аспект | Реализация |
|--------|-----------|
| Защита от race condition | `asyncio.Lock` для каждой комнаты + `asyncio.Lock` для ID |
| Защита от инъекций | `DANGEROUS_CHARS` — фильтрация `=`, `+`, `-`, `@` в начале строки |
| Rate limiting | 1 секунда между запросами (TG middleware + VK декоратор) |
| Soft Delete | Статус "Отменено" вместо физического удаления строки |
| Логирование | RotatingFileHandler 5MB + 3 бэкапа + stdout |
| Graceful shutdown | Обработка SIGINT/SIGTERM, корректная отмена задач |

## 📝 FAQ

**Q: Бот не запускается, ошибка "Service account not found"**
A: Проверьте, что `data/service_account.json` существует и путь правильный.

**Q: Ошибка "Spreadsheet not found"**
A: Проверьте ID таблицы в `.env` и убедитесь, что сервисный аккаунт имеет доступ Editor.

**Q: Бот не отвечает на сообщения**
A: Проверьте логи в `logs/bot.log`. Возможные причины: неверный токен, бот не добавлен в сообщество (VK), webhook не удалён.

**Q: Как посмотреть все бронирования?**
A: Откройте Google Таблицу — все данные в листе `bookings`.

**Q: Можно ли изменить шаг бронирования?**
A: Да, в `config.py` измените `BOOKING_STEP_MINUTES = 30`.

**Q: Как изменить рабочие часы?**
A: В `config.py` измените `WORK_DAY_START` и `WORK_DAY_END`.

**Q: Напоминания не приходят**
A: Проверьте, что фоновый scheduler запущен (в логах должно быть `✅ Reminder scheduler запущен`). Убедитесь, что в таблице есть колонка K "Уведомление".

**Q: Админ-панель не появляется**
A: Проверьте `TG_ADMIN_IDS` и `VK_ADMIN_IDS` в `config.py`. Убедитесь, что ваш ID правильный.
